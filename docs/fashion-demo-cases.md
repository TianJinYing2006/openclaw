# 穿搭 Agent 演示用例

日期：2026-07-31

## 目标

验证微信入口能通过 `fashion_consultant` 工具触发穿搭管道，并输出适合微信阅读的文案。第一版演示只覆盖文本穿搭咨询，不展示衣橱、换衣、商品推荐和长期记忆。

## 推荐演示顺序

1. 海边场景

   用户输入：

   ```text
   今天去海边玩，天气比较热，帮我推荐一套穿搭
   ```

   期望结果：
   - 能触发 `fashion_consultant`
   - 输出最终方案，包含上衣、下装、鞋子、可选配饰
   - 解释透气、防晒、度假感等理由
   - 给出 1-2 个备选风格

2. 婚礼场景

   用户输入：

   ```text
   周末参加朋友婚礼，想穿得正式一点但不要太抢风头
   ```

   期望结果：
   - 能识别正式场合
   - 文案避免过度夸张或不合礼仪的建议
   - 推荐理由要说明正式度和分寸感

3. 通勤场景

   用户输入：

   ```text
   明天上班开会，帮我搭一身看起来干净利落的
   ```

   期望结果：
   - 能识别通勤/工作场景
   - 输出偏稳妥、利落、易执行的方案
   - 给出鞋包或外套方面的实用建议

4. 模糊输入

   用户输入：

   ```text
   随便推荐一套今天能穿的
   ```

   期望结果：
   - 即使信息不足也能给出日常兜底方案
   - 不一次性追问大量问题

5. 风格偏好输入

   用户输入：

   ```text
   我想要一套偏街头感但不要太浮夸的穿搭
   ```

   期望结果：
   - 能保留用户风格偏好
   - 方案和备选风格有差异，不都是同一种休闲风

## 观察日志

本地建议开启：

```properties
app.ai.trace.enabled=true
logging.level.com.example.ykdsummer.ai.fashion=INFO
```

重点看：
- `ToolRegistry collected` 日志中是否包含 `fashion_consultant`
- `Fashion pipeline started` 是否出现
- `Step 1` 到 `Step 5` 是否完整结束
- 如果某个 Agent 失败，Formatter 不应把内部异常直接展示给微信用户
