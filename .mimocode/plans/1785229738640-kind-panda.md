# 用户自定义定时提醒功能实现计划

## ✅ 实现状态：已完成

## 1. 需求概述

实现用户通过微信设置定时提醒的功能，支持：
- 固定间隔（如每30分钟提醒一次） ✅
- Cron表达式（如每天8:00、每周一9:00） ✅
- 一次性定时（如30分钟后提醒、明天8:00提醒） ✅
- 任务持久化到数据库，应用重启后自动恢复 ✅

## 3. 数据库设计

### 3.1 定时任务表 `schedule_task`

```sql
CREATE TABLE schedule_task (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL,                    -- 微信用户ID
    context_token TEXT NOT NULL,              -- 会话token，用于发送消息
    task_name TEXT NOT NULL,                  -- 任务名称/描述
    task_type TEXT NOT NULL,                  -- 任务类型：ONCE/INTERVAL/CRON
    task_status TEXT NOT NULL DEFAULT 'ACTIVE', -- 状态：ACTIVE/PAUSED/COMPLETED/CANCELLED
    
    -- 定时配置
    cron_expression TEXT,                     -- Cron表达式（CRON类型使用）
    interval_seconds INTEGER,                 -- 间隔秒数（INTERVAL类型使用）
    execute_at DATETIME,                      -- 执行时间（ONCE类型使用）
    
    -- 执行内容
    message_template TEXT NOT NULL,           -- 提醒消息模板
    
    -- 执行记录
    last_execute_time DATETIME,               -- 上次执行时间
    next_execute_time DATETIME,               -- 下次执行时间
    execute_count INTEGER DEFAULT 0,          -- 已执行次数
    
    -- 元数据
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    expires_at DATETIME                       -- 过期时间（可选）
);

CREATE INDEX idx_schedule_task_user ON schedule_task(user_id);
CREATE INDEX idx_schedule_task_status ON schedule_task(task_status);
CREATE INDEX idx_schedule_task_next_execute ON schedule_task(next_execute_time);
```

### 3.2 执行日志表 `schedule_task_log`

```sql
CREATE TABLE schedule_task_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER NOT NULL,
    execute_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    execute_status TEXT NOT NULL,             -- SUCCESS/FAILED
    error_message TEXT,
    FOREIGN KEY (task_id) REFERENCES schedule_task(id)
);
```

#### ScheduleTaskExecutor - 任务执行器

```java
@Service
public class ScheduleTaskExecutor {
    
    private final ILinkBotService botService;
    private final ScheduleTaskService taskService;
    
    // 每秒检查待执行任务
    @Scheduled(fixedDelay = 1000)
    public void executePendingTasks() {
        List<ScheduleTask> tasks = taskService.getPendingTasks(LocalDateTime.now());
        for (ScheduleTask task : tasks) {
            executeTask(task);
        }
    }
    
    private void executeTask(ScheduleTask task) {
        try {
            // 替换消息模板中的变量
            String message = processTemplate(task.getMessageTemplate());
            // 发送消息
            botService.sendText(task.getUserId(), task.getContextToken(), message);
            // 更新执行记录
            taskService.updateTaskAfterExecution(task.getId(), true, null);
        } catch (Exception e) {
            taskService.updateTaskAfterExecution(task.getId(), false, e.getMessage());
        }
    }
}
```

## 8. 注意事项

### 8.1 contextToken管理

- contextToken可能过期，需要实现刷新机制
- 考虑存储多个token，按优先级使用
- 失败时通知用户重新发送消息以获取新token

### 8.2 性能考虑

- 轮询间隔不宜过短，建议1-5秒
- 使用数据库索引优化查询
- 考虑使用Redis缓存热数据

### 8.3 并发安全

- 使用数据库锁防止重复执行
- 考虑分布式部署的幂等性

### 8.4 用户确认的设计决策

| 决策项 | 选择 | 说明 |
|--------|------|------|
| 消息模板 | 固定文本 | 只支持固定文本，如"该吃药了"，不支持变量替换 |
| 过期处理 | 自动删除 | 一次性任务执行完成后自动删除记录 |
| 失败重试 | 有限重试 | 最多重试3次，间隔递增（如1分钟、5分钟、15分钟） |

### 9.3 关键技术点

- **工具注入**：通过`ToolArtifactCollector`获取当前用户的userId和contextToken
- **并发处理**：ScheduleTaskExecutor使用`initialDelay=10000`延迟启动，避免数据库初始化竞争
- **失败重试**：最多3次，间隔递增（1、5、15分钟）
