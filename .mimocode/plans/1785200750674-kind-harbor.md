# 定时功能分析：能否写成 Tool？

## 结论

**可以，但需要两部分配合：Tool 只负责"管理"，后台服务负责"执行"。**

---

## 项目现状

| 项目 | 现状 |
|------|------|
| 框架 | Spring Boot 3.5.16 + Spring AI 1.1.8 (Java 21) |
| 数据库 | SQLite (MyBatis-Plus)，已有 `chat_session` / `chat_message` 两张表 |
| Tool 体系 | 40+ 个 `@Tool` 注解方法，由 `ToolRegistry` 自动扫描注册 |
| 定时调度 | `@EnableScheduling` 已启用，`FileCleanupService` 是唯一的 `@Scheduled` 示例 |
| 主动发消息 | `ILinkBotService.sendText(toUserId, contextToken, text)` 可向用户主动推送 |

---

## 架构设计

定时功能天然分成两层：

### 第一层：Tool（LLM 可调用的管理接口）

适合做成 `@Tool` 的部分——让用户通过自然语言管理定时任务：

```
@Tool create_scheduled_task   → 创建定时任务（存入 SQLite）
@Tool list_scheduled_tasks    → 查看我的定时任务
@Tool delete_scheduled_task   → 删除某个定时任务
@Tool update_scheduled_task   → 修改定时任务
```

**为什么适合做 Tool：**
- 项目已有成熟的 Tool 注册机制（`ToolRegistry` 自动扫描 `@Tool` 注解）
- 用户可以通过微信自然语言说"每天早上8点提醒我喝水"，LLM 调用 `create_scheduled_task`
- 与现有 40+ Tool 的开发模式完全一致：`@Component` + `@Tool` + `@ToolParam`

### 第二层：后台执行引擎（不是 Tool）

需要一个独立的后台服务来**轮询并触发**到期任务：

```
@Scheduled(fixedDelay = 30s)  → 扫描 scheduled_task 表
                              → 找到到期任务
                              → 通过 ILinkBotService.sendText() 推送给用户
                              → 更新任务状态（下次执行时间 / 标记完成）
```

**为什么不能只靠 Tool：**
- Tool 是被动的——只有 LLM 调用时才执行
- 定时触发需要主动运行，不依赖用户发消息
- 这与 `FileCleanupService` 的模式完全一致

## 需要新增的组件

### 1. 数据库表（在 `SqliteInitializer` 中添加）

```sql
CREATE TABLE IF NOT EXISTS scheduled_task (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id VARCHAR(64) NOT NULL,
    task_type VARCHAR(20) NOT NULL,        -- 'once' | 'cron' | 'interval'
    cron_expression VARCHAR(100),           -- cron 表达式（task_type=cron 时）
    interval_seconds INTEGER,              -- 间隔秒数（task_type=interval 时）
    execute_at DATETIME,                   -- 执行时间（task_type=once 时）
    content TEXT NOT NULL,                  -- 提醒内容
    enabled INTEGER DEFAULT 1,             -- 是否启用
    last_executed_at DATETIME,             -- 上次执行时间
    next_execute_at DATETIME,              -- 下次执行时间
    created_at DATETIME DEFAULT (datetime('now','localtime')),
    updated_at DATETIME DEFAULT (datetime('now','localtime'))
);
```

### 2. Entity + Mapper + Service（遵循现有 `wechat` 包模式）

```
src/main/java/com/example/ykdsummer/scheduler/
├── entity/ScheduledTask.java        -- MyBatis-Plus Entity
├── mapper/ScheduledTaskMapper.java  -- Mapper 接口
├── service/ScheduledTaskService.java -- CRUD 服务
└── ScheduledTaskExecutionService.java -- @Scheduled 轮询执行服务
```

### 3. Tool 类（遵循现有 Tool 模式）

```
src/main/java/com/example/ykdsummer/ai/tool/ScheduledTaskTools.java
```

参考 `BfrTools` 的最简模式：
- `@Component` + `implements AiTool`
- 注入 `ScheduledTaskService`
- 方法用 `@Tool` 注解，参数用 `@ToolParam` 注解

### 4. 注册到 Gateway

在 `SpringAiChatCompletionsGateway` 的 `generate()` 方法中添加：
```java
if (scheduledTaskTools != null) {
    addToolCallbacks(callbacks, scheduledTaskTools);
}
```

## 关键设计决策

| 决策点 | 建议 |
|--------|------|
| 定时精度 | 轮询间隔 30 秒足够（用户场景是提醒，不是毫秒级调度） |
| 任务持久化 | SQLite（与现有数据一致） |
| 消息推送 | 复用 `ILinkBotService.sendText()` |
| 需要 contextToken | 需要在创建任务时保存用户的 contextToken，否则无法主动推送 |
| 一次性 vs 循环 | 支持两种：`once`（到点执行后删除/禁用）和 `cron`（重复执行） |
| 用户隔离 | 按 `user_id` 隔离，每个用户只能管理自己的任务 |

---

## 关于 contextToken 的注意事项

`ILinkBotService.sendText()` 需要 `toUserId` 和 `contextToken` 两个参数。`contextToken` 来自微信消息上下文，可能有时效性。需要：
1. 在创建定时任务时保存当前的 `contextToken`
2. 如果 token 过期，可能需要通过 SDK 的其他方式获取新的 token
3. 或者探索 SDK 是否有不依赖 contextToken 的发送方式
