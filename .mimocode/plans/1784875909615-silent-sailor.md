# Plan: Simplify application.properties - Remove Placeholders

## Context
The project uses `${ENV_VAR:default}` placeholder syntax extensively in `application.properties`, but:
1. The project runs locally using `application-local.properties` (not via environment variables)
2. `secret.properties` exists but is NOT loaded (no `@PropertySource` or `spring.config.import`)
3. Secrets are already hardcoded as default values in the placeholders
4. Some values are already hardcoded directly (e.g., `app.tts.enabled=true`)

## Changes

### 1. Simplify `application.properties`
Remove all `${ENV_VAR:default}` patterns, keep only the default values.

**Before:**
```properties
spring.ai.openai.api-key=${SPRING_AI_API_KEY:${AI_API_KEY:sk-cyqti0d3xzilztmztzrqkehkiedo425bymemoeatgc0doqbm}}
```

**After:**
```properties
spring.ai.openai.api-key=sk-cyqti0d3xzilztmztzrqkehkiedo425bymemoeatgc0doqbm
```

### 2. Delete `secret.properties`
- File is dead code (not loaded anywhere)
- Contains plaintext secrets tracked in git (security issue)
- Secrets are already in `application.properties` defaults

### 3. Update `.gitignore`
- Remove reference to `application-local.properties` if not already present
- Ensure `application-local.properties` is properly gitignored

## Files to Modify
- `src/main/resources/application.properties` - Remove placeholders
- `src/main/resources/secret.properties` - DELETE
- `.gitignore` - Verify coverage

## Verification
1. Run `mvn spring-boot:run -Dmaven.test.skip=true` to verify startup
2. Verify all properties load correctly
3. Check that `application-local.properties` overrides work as expected

## Risks
- **None for local development** - defaults are preserved
- **Environment variable override will change** - must use property names instead of env var names (but user confirmed they don't use this)
